# fleet-serving

The Kubernetes controller for [Fleet](https://github.com/zlogic-labs/fleet).
It reconciles `FleetModel` and `FleetDeployment` custom resources into native
Kubernetes objects, and reports what the cluster actually contains to a Fleet
control plane.

This is a separate repository because Fleet's gateway must not be able to
reach for `client-go`. That separation is enforced by the module graph: nothing
under `fleet/core` imports a Kubernetes library, so a gateway binary cannot
acquire one by accident.

## What it does

- **`FleetModel`** — a weight format, a context limit, and a tokenizer, with
  the format inferred from what was pulled rather than declared by hand.
- **`FleetDeployment`** — replicas, tensor/pipeline parallel size, engine and
  resources. The renderer turns it into a `Deployment` plus a `Service`, and
  records the engine's real address and version in `status`.
- **Inventory reporting** — every `--report-every` interval it counts nodes,
  GPUs, memory and per-deployment state and `PUT`s the result to
  `/api/v1/inventory` on a Fleet control plane. That is the entire interface
  between the two repositories; this side never calls back into the gateway.

The contract types live in `core/pkg/inventory` and are shared rather than
duplicated, so a change to one side that breaks the other is a compile error
rather than a runtime surprise.

## Build

```sh
make build           # ./bin/fleet-operator, regenerating the CRDs first
make check           # gofmt + go vet + tests
make build-release   # linux/amd64, linux/arm64, darwin/arm64
```

Requires Go 1.26+. No cgo anywhere in the dependency graph.

The CRD manifests under `config/crd/bases/` and the deepcopy functions under
`api/v1alpha1/zz_generated.deepcopy.go` are generated by `make manifests` and
committed. Apply them before installing the controller:

```sh
kubectl apply -f config/crd/bases/
kubectl apply -f config/samples/
```

## Run

```sh
./bin/fleet-operator \
  --namespace fleet \
  --report-to http://127.0.0.1:8081 \
  --report-every 30s \
  --cluster-name k3s-dev
```

`--report-to` and `--cluster-name` are optional: without them the controller
still reconciles, it simply has nowhere to report. `--report-every` defaults to
30 seconds.

## Developing against a local Fleet checkout

The module pins a released version of `fleet/core`. To build against an
unreleased one, create a `go.work` (it is gitignored):

```sh
cat > go.work <<'EOF'
go 1.26.4

use .

replace github.com/zlogic-labs/fleet/core => ../fleet/core
EOF
```

The replacement belongs in `go.work` rather than `go.mod` because a `replace`
in `go.mod` travels to every downstream consumer of this module.

### Two independent version numbers

- **The Go module version** (`fleet/core v0.2.0`) is bumped when `core` gains
  symbols this module uses.
- **The wire contract version** (`inventory.ContractVersion`, currently 1, and
  the `/api/v1` path) is bumped only when the report format changes in a way
  the rules in [the contract
  document](https://github.com/zlogic-labs/fleet/blob/master/docs/inventory-contract.md)
  forbid.

Bumping one does not bump the other.

### After bumping the pin

A `go.work` with a local replace hides a pin that no longer exists. Build once
with the workspace off, or the published module is the one nobody tested:

```sh
GOWORK=off go build ./... && GOWORK=off go test ./...
```

## Tests

`make check` covers the packages here. The end-to-end test — CRD applied,
deployment reconciled, a real model served, a real inference routed through the
Fleet gateway — lives in the main repository as `make e2e`, because it needs
both checkouts. Clone the two side by side and it finds fleet-serving on its
own; otherwise set `FLEET_SERVING_DIR`.
